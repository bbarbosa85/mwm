Quick start

Five minutes from download to your first shortcut.

  1. Install MWM

    Open MWM.dmg and drag MWM to Applications, then open it. MWM has no Dock icon; it lives in the menu bar at the top right. It needs macOS 12 or later and runs on Apple silicon and Intel.

  2. Open it the first time

    MWM is signed but not notarized, so macOS may say it can't check it for malicious software. Choose System Settings → Privacy & Security → Open Anyway, or right-click MWM and choose Open, or run once:

    xattr -dr com.apple.quarantine /Applications/MWM.app

  3. Allow Accessibility

    macOS only lets an app move other apps' windows with your permission. MWM asks on first launch: choose Open System Settings and turn on MWM under Privacy & Security → Accessibility.

  4. Add your first shortcut

    Click the MWM icon in the menu bar and choose Configure MWM… (⌘,). On Keyboard, pick a group on the left (create one such as hyper under Modifiers first if you have none), click a free key and choose Add Shortcut. Pick an action, Record or Pick on map the keys, then Save. Press Apply at the bottom to restart MWM with the change.

Optional

  • Try a default shortcut. Open Finder and another app, then press ⌥⇧F to jump to Finder, or ⌘esc for window hints. The defaults work until you add your own configuration.
  • Name your displays. On Displays, press Add next to a screen to name it, so shortcuts can send windows to it. See Monitors.
  • Save a snapshot. Arrange your windows, open Snapshots, name the New snapshot card and press Save. Restore puts everything back. See Snapshots.
Prefer a file? Copy an example to ~/.mwm.yml, open Configure MWM… and press Apply.

The configuration window

Open it from the menu bar (Configure MWM…) or with ⌘,. The sidebar has three groups. Changes are saved to ~/.mwm.yml as you make them; Apply restarts MWM so they take effect. The bar at the bottom says whether the file is valid.

Keyboard

Every shortcut, two ways. Switch with Map | List at the top right.

  • Map: a Mac keyboard. Pick a modifier group on the left and keys are colored by what they do there: blue moves to a slot, green focuses apps and windows, purple is a feature, orange is a conflict, yellow is a key macOS keeps. Click a key to see "Press … to …", then Edit, Remove or Add Shortcut.
  • List: search, and filter by what it does, by group, or only conflicts. Each row has an on/off switch.

Adding and editing a shortcut

The editor has a list of what the shortcut can do on the left (Focus app, Move to, Focus window, Resize, Nudge, Push, Throw to screen, Save snapshot, Restore snapshot, Window hints, Grid, Switch windows, Relaunch, Advanced…) and its settings on the right.

  • Record: press the keys you want. Enter uses them, Esc cancels.
  • Pick on map: choose a group and a key on the keyboard. Keys already used in that group are colored. In Custom you toggle the modifiers yourself.
  • Combinations macOS keeps (⌘S, ⌘Q …), and any key with no modifier, can't be saved.
  • A warning appears if another shortcut already uses the same keys.

Modifiers

Named groups of modifier keys, like hyper = ⌃⌥⌘. Shortcuts that use a group are shown under its name.

Displays

Lists the screens that are connected and gives each a name. Add next to a screen names it (for example laptop); MWM finds it again by its model whenever it is plugged in. Identical monitors are numbered left to right.

Slots

Named areas of the screen. The built-in presets (halves, thirds, quarters and rows) are locked and shown on the Presets side; your own are on Custom. New Slot opens a canvas where you drag a slot or type exact percentages, with a grid to snap to and a preview on each connected screen.

Snapshots

Cards for each saved arrangement, ending with a New snapshot card. See Snapshots.

General, Advanced, Other aliases and Backup

General has everyday settings (startup, windows, window hints, keyboard layout, config file) and Advanced the rest (nudge and resize, held keys). Other aliases lists named text that doesn't fit elsewhere. Backup is coming soon.

The configuration file

MWM keeps everything in one plain-text file, ~/.mwm.yml. It is data, not code: MWM reads it and nothing in it is ever run. The configuration window edits it for you, and you can edit it by hand too.

When the window saves, it rewrites the file, so comments you add by hand are not kept. Keep notes in a shortcut's note field instead.

The file has a version: 2 line and up to six sections:

version: 2

settings:           # global options (name: value)
  defaultToCurrentScreen: true

modifiers:          # named groups of modifier keys
  hyper: [ctrl, alt, cmd]

monitors:           # your screens, by name
  laptop: {display: built-in}

slots:              # named areas of the screen
  left-two-thirds: {x: 0%, y: 0%, width: 66.666667%, height: 100%}

aliases: {}         # any other named text

bindings:           # the shortcuts
  - key: left
    mods: hyper
    action: {type: move, slot: lefthalf}

YAML you can use

MWM reads a strict subset of YAML so a file never loads differently from how it reads: block mappings and lists, one-line lists and mappings ([a, b], {x: 0%, y: 0%}), plain or quoted text, numbers, true/false and # comments. Anchors, tags, multi-line strings and brackets that span several lines are errors that name the line. Quote a value that starts with a special character or contains : or #.

Names

Modifiers, monitors, slots and aliases share one set of names, so each name can be used once. Fields that take a name (mods, slot, screen) take it plain. In free text (aliases, custom actions, slot formula) write it as ${name}.

Older files

Files without version: still load. At startup MWM converts them to version 2 and keeps the old one next to it as ~/.mwm.yml.v1-<timestamp>. See Moving from Slate.

Settings

Global options, written as name: value under settings:. Values are text, numbers or true/false; a list is joined with ;. Anything you leave out uses its default.

Modifiers

A named group of modifier keys, so shortcuts can say mods: hyper instead of listing keys.

modifiers:
  hyper: [ctrl, alt, cmd]
  shyper: [shift, ctrl, alt, cmd]

The modifier names are ctrl, alt (Option), shift, cmd and fn. A shortcut that lists the same keys written out is shown under the group's name, so the two stay interchangeable.

Monitors

Give each screen a name once, then send windows to it by name. One object per monitor:

monitors:
  laptop: {display: built-in}
  desk: {display: "Studio Display", size: 5120x2880}
  old: {screen: "1"}
FieldWhat it is
displayThe screen's model: built-in, or its name such as Studio Display. Identical displays are numbered left to right with #1, #2.
screenAn older kind of reference, for hand-written files: a number such as "0", ordered:1, next. Use display or screen, not both.
sizeThe screen's size (5120x1440), used by slots drawn for that screen. A monitor with only a size is just that size.

A display that isn't connected counts as "the screen you're on", so a shortcut still does something. Names keep any prefix you give them (the window suggests monitor-samsung); they are shared with slots and aliases.

Slots

A slot is a named rectangle of the screen. Write it as percentages of the screen:

slots:
  center-column: {x: 16.666667%, y: 0%, width: 66.666667%, height: 100%}
  reading: {x: 30%, y: 0%, width: 40%, height: 100%}

x and y are from the top left. Percents can have decimals (up to six). For an area that depends on the window or on another screen, use a formula instead:

slots:
  wide-with-gap: {formula: "move (screenOriginX+screenSizeX/5)+14;screenOriginY (4*screenSizeX/5)-14;screenSizeY"}

Built-in presets

These exist without being written in the file, and their names are reserved:

fulllefthalfrighthalftophalfbottomhalfthird1third2third3thirdrow1thirdrow2thirdrow3quarter1quarter2quarter3quarter4quarterrow1quarterrow2quarterrow3quarterrow4

A slot of your own can't reuse a preset's name, and can't be the same area as another slot.

Aliases

Named text for anything that doesn't fit another section. Use it as ${name} in other aliases, custom actions and slot formulas.

aliases:
  gap: "14"
slots:
  padded: {formula: "move screenOriginX+${gap};screenOriginY+${gap} screenSizeX-2*${gap};screenSizeY-2*${gap}"}

Aliases can use other aliases; a name that doesn't exist, or a loop, is an error that names the place.

Bindings

A list of shortcuts. Each has the keys that trigger it and an action:

bindings:
  - key: left
    mods: hyper
    action: {type: move, slot: lefthalf}
    group: Windows
    note: Left half
FieldWhat it is
keyThe key, from the key names.
modsA modifier group by name (hyper) or a list ([alt, shift]). A key with no modifier is not allowed in the window; it would stop you typing.
actionWhat it does, an object with a type. See Actions.
group optionalA heading to file it under.
note optionalA reminder, shown in the window.
enabled optionalfalse switches it off without deleting it.
repeat optionaltrue or false to repeat while held, instead of the action's own habit.

Two enabled bindings on the same keys conflict: only one of them works. The window shows which.

An action is an object with a type and the fields that type takes. An action with no fields can be written as plain text (action: relaunch).

focus-appappBrings a running app to the front, by name.
focusdirectionFocuses the window left, right, up, down or behind the current one.
throwscreen, optional styleSends the window to another screen: a monitor name, a number, next or previous. style: resize fits it to the new screen.
nudgex, yMoves the window by pixels (+50) or a percent (+10%).

Examples

action: {type: move, slot: third2, screen: desk}
action: {type: focus-app, app: Google Chrome}
action: {type: throw, screen: next, style: resize}
action: {type: resize, x: +10%, y: +0}
action: {type: push, direction: left, options: "bar-resize:screenSizeX/3"}
action: {type: hint, letters: ASDFJKL}
action: {type: save-snapshot, name: work, keep: true}
action: {type: custom, text: "chain push up | push right"}

When a binding can't be written as fields (extra spaces, different quoting), the window keeps its text as custom so saving never changes what it does.

Snapshots

A snapshot remembers every window (its app, title, position and size) and the screens that were connected. Restoring it moves each open window back, matching windows to the saved ones by title.

  • Save: from the New snapshot card on the Snapshots page, the menu bar, or a save-snapshot shortcut. Names can't contain spaces, so a shortcut can refer to them.
  • Restore: the card's Restore button, the menu bar, or a restore-snapshot shortcut. Windows that are no longer open are skipped.
  • Keep after restart: the pin. A pinned snapshot is written to disk; an unpinned one is forgotten when MWM quits. Snapshots live in ~/Library/Application Support/com.bbarbosa85.mwm/snapshots, not in ~/.mwm.yml.
  • Update with current windows: in a card's ⋯ menu. It records the windows as they are now over that snapshot, keeping its name and pin.
  • Screens: a card draws the screens it was taken on. A dashed screen isn't connected now, and the card says "screen missing". Restoring still works, with windows landing on the screens you have.
Restoring and saving read and move other apps' windows, so they need the Accessibility permission.

Slot formulas

A slot's formula is a move operation: move <x>;<y> <width>;<height>, optionally followed by a screen size. Numbers can be expressions with these variables. Spaces aren't allowed inside an expression (screenSizeX/2, not screenSizeX / 2).

VariableMeaning
screenOriginX, screenOriginYTop-left corner of the target screen
screenSizeX, screenSizeYWidth and height of the target screen
windowTopLeftX, windowTopLeftYWhere the window is now
windowSizeX, windowSizeYThe window's current size

Operators are + - * / and **, with min, max, floor, ceiling, abs, sqrt and more. A slot written as percentages is turned into the same kind of formula, such as move screenOriginX+screenSizeX/3;screenOriginY screenSizeX/3;screenSizeY.

slots:
  left-with-gap: {formula: "move screenOriginX+10;screenOriginY+10 screenSizeX/2-15;screenSizeY-20"}

Moving from Slate

MWM is a fork of Slate, so its old files still work.

  • ~/.slate and ~/.slate.yml are converted into ~/.mwm.yml on first launch, and the old files are kept as backups. If you already have a ~/.mwm.yml, MWM asks whether to merge.
  • JavaScript configurations (~/.slate.js) can't be converted: MWM no longer runs code from a configuration. The file is set aside and an alert says so.
  • Older ~/.mwm.yml files (without version:) are rewritten once as version 2, keeping the old file as ~/.mwm.yml.v1-<timestamp>. If the conversion wouldn't be exact, the file is left as it is.
  • Not carried over: layout, default and source lines and per-app settings; the alert lists them.

The classic operations (chain, sequence, corner, layout, shell, hide …) still work as custom actions; see the operations reference.

Troubleshooting

Windows don't move

Almost always the Accessibility permission. In System Settings → Privacy & Security → Accessibility, check MWM is on. If it is, select it, press − to remove it, add it again, then choose Reload Configuration. macOS ties the permission to the exact app that was approved; MWM keeps it across updates when the new version is signed with the same certificate.

A shortcut does nothing

  • Press Apply (or Reload Configuration) after changing shortcuts.
  • Look for a conflict: the map shows it in orange and the list has a Conflicts filter.
  • Another app, or macOS, may already own the keys.
  • A focus-app shortcut needs the app to be running, and its name must match exactly (Google Chrome, not Chrome).

The window shows an error

The bar at the bottom names the line. A file that can't be read as a form stays on disk untouched; fix it in a text editor and reopen the window.

Start over

Quit MWM and move ~/.mwm.yml out of the way. MWM starts with its defaults again. Your old file, and the .bak and .v1-… copies next to it, are untouched.
